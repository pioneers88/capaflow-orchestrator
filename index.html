    Known limitations
    • Handles only two synthetic OOS cases for one fictional product (Xorbitacycline, batches XB-2026-546067 / XB-2026-547112) — not tested against real manufacturing data, other products, or higher case volumes.
    • English-language, plain-text data only, in the exact embedded record shape used here — no file upload, OCR, or connection to a real LIMS/SCADA/ERP system; malformed or differently-shaped data is not handled.
    • Processes one case at a time, one API call per run — no persistent memory across cases or sessions. The Run Log and Eval results live in this browser's local storage only; they are not shared across users or synced to a system of record.
    • Legal/regulatory and boundary detection depend on the system prompt's explicit rules; phrasing outside what it's been told to catch may slip through. Separately, Anthropic's own API safety classifier can also block a request independent of this app's logic — confirmed reproducibly (3/3 runs each) on both regulatory-trap eval cases: the hardened variant (specific batch numbers, "shipped to distributors") and the fully paraphrased variant (zero trigger words, "shipped to wholesalers"). Both were blocked before the agent's own reasoning ever ran. This means the escalation logic for this entire category of regulatory-substance case is currently untestable through this API, not proven broken or proven working — a real, recurring constraint of building on a hosted model with its own safety layer, distinct from any gap in this app's own rules.
    • The "coordinator name" field is a plain text label for attributing Run Log entries — it is not authentication, and does not verify who is actually typing.
